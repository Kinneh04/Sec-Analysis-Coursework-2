How a verdict is built

  1. Model score. The pretrained EMBER2024 model scores 2,568 static measurements of the file. When Binary Ninja features are available, the V8 blend adds a second model's view of the code; otherwise EMBER2024 decides alone. The score runs from 0 to 1 on one display scale (not a calibrated probability). At or above {{ '%.4f' % thr }} the file is Malicious; {{ '%.4f' % border }} up to the threshold is Borderline (shown, not flagged); below {{ '%.4f' % border }} is Benign. Each report says which path decided it.
  2. Reasons. Each measurement's contribution (SHAP) is translated into a sentence and compared with typical benign and malware values from training. Contributions are grouped into the factor groups below to give the Score breakdown.
  3. Context signals. Facts shown as context, not as model inputs in this form: signature validity and signer (EMBER2024 reads only the signature's structure), installer format, API capabilities, structure. Each says what it means and how often it is harmless.
  4. Assessment. A heuristic note that correlates the reasons with the signals, e.g. "flagged, but every strong reason is explained by the NSIS installer format and the file is validly signed". It never changes the model verdict; the analyst records the final decision.
